# SureLM - Detailed Architecture Document

**Version:** 0.1  
**Date:** July 2026  
**Project:** Indian Rural Insurance Ecosystem Platform

---

## **1. SYSTEM OVERVIEW**

### **Mission**
SureLM is an AI-powered hybrid retrieval system enabling grassroots insurance agents to serve rural/semi-urban Indian communities through:
- Intelligent policy recommendations
- Multilingual AI assistance (regional language support)
- Automated OCR document processing (Aadhaar, PAN, KYC)
- Agent CRM with lead management & reminders

### **Architecture Pattern**
Monorepo Next.js 16 application with modular microservice-style components integrated via shared primitives.

## **4. DATABASE SCHEMA (PRISMA)**

### Core Entities:

**User & AgentProfile**
- clerkId: Clerk auth ID
- role: AGENT | ADMIN
- agentProfile with location, language fields

**PolicyLead (Household)**
- agentId, householdName, phone
- income, familySize
- status: NEW | CONTACTED | POLICY_ISSUED | REJECTED
- dateOfBirth for birthday tracking
- followUpAt for visit scheduling

**PolicyIssuance**
- leadId, policyName, premiumAmount
- issuedAt, expiresAt
- nextPremiumDue (auto-calculate renewal)
- status: ACTIVE | EXPIRED | CLAIMED

**Document & Chunk System**
- Document: filename, chunks[] (text chunks for FTS)
- Brochure: basename (deduplication), pdfData (binary), versionHash (MD5)
- Chunk: content, chunkOrder, pageNumber, category (header detection)

**Reminder System**
- Reminder: leadId, type (FOLLOWUP | BIRTHDAY), scheduledAt
- BirthdayReminder: daysUntil, wishSent flags

**Observability Models**
- AuditLog: action, entityType, entityId, requestTraceId
- AIRequestLog: endpoint, modelUsed, tokens, latency, confidenceScore

## **5. RETRIEVAL ARCHITECTURE**

### Hybrid Search System (3 parallel channels):

1. **PostgreSQL Full-Text Search (Lexical)**
   - Target: Policy names in PolicyIssuance
   - Method: ts_rank() + plainto_tsquery()
   - Use case: Exact term matching

2. **Qdrant Vector Search (Semantic)**
   - Target: content_chunks collection
   - Method: Cosine similarity on 768-dim embeddings
   - Use case: Natural language queries

3. **User History Lookup (Personalization)**
   - Target: Agent's past PolicyIssuance records
   - Method: JOIN on agent relationships
   - Use case: Personalized context

### Scoring:
- High: score >= 0.7 (strong match)
- Medium: score >= 0.4 (acceptable)
- Low: score < 0.4 (weak)

## **6. AI ORCHESTRATION LAYER**

### Embeddings Pipeline
- Endpoint: http://localhost:11434/api/embeddings
- Model: nomic-embed-text (768-dim)
- Batching: Sequential for VRAM protection

### LLM Pipeline
**Primary:** Ollama qwen2.5-coder:1.5b  
**Fallback:** Ollama llama3:latest

**Failover Logic:**

## **7. PDF PROCESSING WORKFLOW**

**Steps:**
1. Extract Text via pdfjs-dist
2. Chunk: 1200 words with 200-word overlap
3. Detect Category via header regex patterns
4. Generate Embeddings sequentially (VRAM-safe)
5. Store Chunks: Prisma transaction (DB + Qdrant)

**Deduplication:** MD5 hash on file content
